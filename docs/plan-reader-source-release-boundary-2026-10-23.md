## Rebuild the local candidate

Run from the framework repository root:

```sh
node scripts/prepare-reader-source-release.mjs --self-test
node scripts/prepare-reader-source-release.mjs --online
```

Without `--online`, installation is strictly offline. The actual offline attempt missed `@types/qrcode` 1.5.6's tarball in the local cache. The authorised `--online` mode permitted ordinary npm registry fetches and passed. Both modes disable lifecycle scripts, apply `min-release-age=7`, use the exact core lockfile and create an isolated npm cache inside disposable repository-local scratch. Only matching public npm registry records and locked integrity objects are copied from the existing cache; the shared cache and shared `node_modules` are not changed.

The script first builds and imports the candidate using a link to core's existing dependencies. It then removes that link and generated output, runs an actual `npm ci`, rebuilds, runs the exported Node tests and imports `reader-core` by its package name in a fresh native Node process. The demo, original worktrees and real books are absent from both build trees. Installation dependencies, generated `dist`, temporary cache and all other verification scratch are removed in `finally`, including on a failed check. Shared core `dist` is untouched.

Inside the completed source candidate, its own commands are:

```sh
npm run setup
npm run build
npm test

```

Those commands install, build and test core only. No missing demo dependency is referenced. The verified toolchain is Node 26.12.1 with npm 11.20.0; the candidate pins the tested Node version. Root package version remains 0.2.0 and core remains 0.1.0.

## Audit and reproducibility

The exporter audits every intended textual file before building and audits the final set after adding notices and provenance. It checks decoded Unix/Windows home paths, local file URLs, known private workspace references and credential-shaped literals. It compares output against 12,831 deduplicated spans derived from the actual private real-book input. The local evidence retains the input hash, counts, book identifiers and anchor hashes; no manuscript passage is printed or exported as audit evidence.

One exact false positive is retained and explained: `file:///etc/passwd` is a generic unsafe URL in a sanitisation regression. Only its single expected occurrence inside the exact adversarial fixture is classified as public-safe. The rest of that file receives every check; a second local file URL still fails. Generic source imports such as `./components/home/Home.js` remain valid relative paths. No whole test, directory or manuscript match is blanket-whitelisted.

The archive uses sorted regular-file members, fixed modes, zero timestamps and owners, and deterministic gzip compression. Its parser checks every member against the exact in-memory bytes, and a second archive generation must be byte-identical. The source candidate is read back after writing, with its exact file set and all bytes checked again against the saved archive. Two complete verification runs produced the same archive hash. The external manifest records every path, byte length and SHA-256, while the checksum file records the archive SHA-256. Verification output and the run's source input hashes remain outside the candidate.

These checks are heuristics and technical preparation evidence. They do not establish rights clearance, public scope approval, browser visual acceptance or final EPUB acceptance. The parent retains the separate integration and review evidence.
