No action needed. This source audit identifies what the online reader redesign can reuse. **Use ReadFlex for typography and the speech contract, WriteFlex for focus behaviour, and UnityBC’s later participant reader for the audiobook experience.**

- ReadFlex supplies a browser-oriented speech package and a compact reading settings model.
- WriteFlex supplies five display-only readability modes and two mutually exclusive overlays; its rendering depends on CodeMirror.
- UnityBC supplies recorded audio, sentence timing, passage navigation and resume, with view changes that preserve playback.

## What can be reused from WriteFlex

The inspected checkout is `/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop`. Its package declares version 0.24.1; this audit makes no claim about an installed app or another worktree.

**Reuse the behaviour and pure helpers; adapt the rendering to the web reader.**

- [The focus implementation](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/editor/focus-modes.ts:21) defines `FocusMode = '' | 'fade' | 'sentence' | 'segment' | 'breakup' | 'anchored'`. These fade other paragraphs, highlight a sentence, dim other sentences, display numbered sentence breaks, or emphasise word beginnings. `effectiveFocusMode()` suppresses sentence, segment and breakup while speech controls segmentation; fade and anchored reading can combine with speech. Stopping speech restores the declared choice.
- [Sentence and word-lead helpers](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/editor/sentences.ts:47) expose `segmentSentences(text, from)` with half-open character ranges, and `leadLength(word)`. These have no library imports and can be copied or extracted directly. The segmentation uses punctuation, abbreviations and sentence openers; it is not established as a universal multilingual segmenter.
- [The overlay contract](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/editor/line-overlay.ts:21) defines `LineOverlayConfig`: line focus has on/off, 1/3/5 lines, light/medium/dark dimming and follow mode; ruler has on/off, thin/1/3/5/all-below coverage, opacity and follow mode. Follow choices are cursor, typewriter, read-aloud and by-hand. **Line focus and ruler are exclusive:** `resolveExclusive()` defaults to line focus when persisted state enables both. Either can combine with a readability mode and speech.
- [The focus picker model](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/components/focus-picker-model.ts:1) provides rows, digit shortcuts 0–7 and arrow/Home/End navigation. [The React picker](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/components/FocusPicker.tsx:48) provides the controls. Preserve this separation between readability and overlays.

`focus-modes.ts`, `anchored-reading.ts` and `line-overlay.ts` use `@codemirror/state` and `@codemirror/view`. They also depend on local search, speech decorations, Markdown block ranges and typewriter follow. They are **not drop-in React article components**. The overlay measures visible visual lines, paints without intercepting pointer events and leaves source text and selection intact. A DOM reader needs equivalent line measurement and an active reading position instead of an editor caret. Styling lives in [the focus CSS](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/writeflex-desktop/src/renderer/src/styles/app.css:2272) and uses WriteFlex colour variables.

Existing regression examples are in `tests/main/focus-modes.test.ts`, `tests/main/line-overlay.test.ts`, `tests/main/focus-picker-model.test.ts`, `tests/browser/anchored-reading.test.ts` and `tests/browser/line-overlay.test.ts`, under the WriteFlex root above. They were not run.

## What can be reused from ReadFlex

The inspected checkout is `/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex`.

**Typography is the most direct UI reuse.** [ReadingPreferences](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/apps/shell/src/renderer/reading-preferences.ts:1) defines serif/sans, text size 12–28, line height 1.2–2.4, column width 480–1080, paragraph spacing 0–40 and light/sepia/dark themes. Reading handles invalid storage with defaults. [The settings hook](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/apps/shell/src/renderer/use-reading-settings.ts:1) persists changes through injected storage and optionally records setting changes. [The reading popover](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/apps/shell/src/renderer/reading-controls-popover.tsx:1) has steppers, reset, pressed states, Escape handling, focus return and Tab containment. It needs React, lucide-react and its CSS. `clean-view.tsx:675` maps preferences to `--reading-*` CSS variables; `clean-view.css` supplies their rendering. Rename the storage key for the online reader. Storage writes currently can throw.

I did not find WriteFlex’s five focus modes or line/ruler overlays in ReadFlex’s authored shell code. ReadFlex contributes typography, speech highlighting and source mapping here.

**The strongest reusable audio boundary is** [@flex/speech](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/packages/speech/src/index.ts:1):

- `Speakable` contains text, block segments and optional pieces mapping spoken offsets back to source offsets. `SpeechPlayer` supplies play/move/restore at a source offset, pause/resume, rate/voice changes and sentence/paragraph skipping.
- `SpeechCapabilities` separates live and rendered sources behind cancel/pause/resume/rate/speak/voice methods and boundary/end/error callbacks. `webSpeechCapabilities()` wraps browser speech synthesis; `renderedSpeechCapabilities()` wraps an audio URL.
- `RenderedAudiobook` carries the URL, alignment, content hash and generation provenance. Alignment points contain character ranges and audio start/end times, with an explicit body-coordinate origin. `renderedOffsetBoundary()` converts between time and reading offsets; within a point it interpolates character position. This is not automatically word-perfect alignment.

This private workspace package has no declared runtime package dependencies, but browser adapters need Web Speech or HTML audio. [The clean-document projection](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/apps/shell/src/renderer/clean-view-speech.ts:37) shows how to retain source offsets while omitting note markers and optionally announcing structure. Adapt it to publication blocks rather than importing ReadFlex’s PDF data model.

[The speech hook](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/apps/shell/src/renderer/use-clean-speech.ts:239) restores source position when replacing the playback capability; it also handles partial recordings and stale artefacts. `chunked-rendered-speech.ts` handles chunk progression and unavailable continuation. These require ReadFlex-specific intentions and artefact types, so reuse their transitions rather than copying the hook wholesale. The simple rendered adapter reports media errors and initial playback refusal, but its `resume()` does not catch a rejected play promise; the chunked adapter does.

Local generation is separate: [speech-synthesis](/Users/dominiklukes/gitrepos/06_apps-utilities/01_desktop-apps/readflex/packages/speech-synthesis/src/index.ts:147) spawns Python and provisions a runtime. Its `pyproject.toml` requires Python 3.11–3.12, MLX, mlx-audio, Misaki and spaCy dependencies; it also needs a Kokoro model. This belongs in a desktop/service preparation path, not a static browser reader. Existing audio can play without those generation dependencies.

## The actual UnityBC audiobook reader

**Use the later participant delivery**, `/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13`, rather than treating the earlier accessible-player experiment as the final pattern. [Its guide](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/README-unitybc-participant-demos.md:1) describes the implemented views and controls. Filenames were searched across the publication/webapp repositories; the matching implementation was located in the UnityBC project.

The reusable source map is:

- [The Czech reference runtime](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/source/participant-unitybc-czech-lay-summary.js:1) contains `window.UnityBCAudio.text()` and `.highlight()`, storage, selection notes, single-language transport and media error handling. Its adjacent `.md` supplies fixed content, translated copy and DOM template; its `.css` supplies layout. These are browser scripts, not an exported component package.
- [Reader view behaviour](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/runtime-unitybc-reader-view.js:1) supplies focus cards, passage skipping, follow-reading, collapsed sidebar and pause-after-segment. Follow-reading avoids scrolling during text selection or textarea editing and keeps the active sentence clear of sticky controls.
- [The bilingual playback engine](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/runtime-unitybc-interpreter.js:2) exposes `UnityBCInterpreter`, constructed with data, mutable state, one audio element, save/copy functions and track/change/completion callbacks. It supports play/pause, go, skip, repeat, seek and leave. [The interpreter view adapter](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/runtime-unitybc-interpreter-view.js:1) connects it to the surrounding reader closure.

**Audio and timing.** [The delivery builder](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/build-unitybc-participant-delivery.py:39) takes translated WAVs from `sample-runs/multilingual-audio-2026-10-12/recordings/` and English WAVs from the delivery’s `english-recordings/`. It converts both to mono 24 kHz, 32 kbps MP3 and embeds base64 tracks by unit and language. Playback creates Blob URLs, requiring no server or runtime provider call. Generation uses GPT Audio Mini/Shimmer; [English assembly](/Users/dominiklukes/gitrepos/04_projects-consultancies/02_active/ai-translation-unitybc/sample-runs/participant-demos-2026-10-13/generate-unitybc-english-audio.py:32) measures concatenated sentence clips to create timing. The multilingual builder similarly assembles sentence clips. Do not substitute estimated reading time for these measured spans.

The data contract contains `units`, each with a stable `id`, text/blocks by language, `tracks[language]`, `alignment[language].sentences` containing `charStart`, `charEnd`, `start`, `end`, and optional `interpreterPairs` with corresponding per-language ranges. Packaging checks paired-text hashes and records MP3 hashes. Meaning pairs come from saved semantic annotations; they are not inferred by the playback engine.

**Resume and UX.** The runtime saves unit, language, speed, per-unit/language seconds, marks and view choices in localStorage under the material identity. Bilingual resume additionally saves pair, language phase and time. Reload restores state without starting playback. Focus/sidebar/display changes preserve playback; switching from bilingual to one language pauses and retains position. Bilingual playback reads English then the translation with a 650 ms transition, honours rate-adjusted segment boundaries and stops at the section end. The visible transport uses round back/play/forward controls and numerical speeds; the later layout hides the progress bar. Follow-reading is optional, and the paused sentence remains highlighted.

**Errors and dependencies.** Missing recordings disable listening; media errors and ordinary play refusals show localised feedback; storage failure writes a status message. The bilingual engine guards stale callbacks with a token and revokes cached URLs on leave, but its rejected play promise only resets running state, without a dedicated error callback. The scripts require their exact DOM selectors and shared closure; they need extraction before React reuse. Runtime dependencies are browser audio, Blob URLs, localStorage and DOM APIs. Rebuilding needs Python, ffmpeg and fixed audio/alignment files. Generation/provider access is a separate workflow. Study recordings and language-review status should not be mistaken for generic reader assets or validation.

## Where this joins the online reader

The framework already has [readability controls](/Users/dominiklukes/gitrepos/07_webapps-websites/05_publications/onlinereaderframework/packages/reader-core/src/components/tools/ReadabilityControls.tsx:1) and [per-book appearance state](/Users/dominiklukes/gitrepos/07_webapps-websites/05_publications/onlinereaderframework/packages/reader-core/src/original/use-publication-reader.ts:36). Map ReadFlex’s richer preferences into that existing state, preserving publication identity and annotation offsets. Use WriteFlex’s display-only focus rules over rendered blocks, ReadFlex’s source-offset speech contract, and UnityBC’s independent playback/view state and passage controls. Recorded audio requires an explicit publication-to-audio alignment adapter; UnityBC’s sentence spans and ReadFlex’s body offsets are different coordinate contracts.
